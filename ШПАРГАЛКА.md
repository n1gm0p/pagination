# Шпаргалка к защите: каталог с пагинацией

Коротко, своими словами. Можно читать как конспект.

## Архитектура: за что отвечает каждый файл

Проект разделён на **базу данных** и **интерфейс**. Страница не лезет в SQLite напрямую — она вызывает функцию.

| Файл | Зачем он нужен |
|---|---|
| `db/schema.ts` | Схема таблицы. Говорит Drizzle: в `products` есть `id`, `title`, `price`, `description`, `image`. Отсюда берётся тип `Product`. |
| `db/index.ts` | Подключение. `better-sqlite3` открывает файл `sqlite.db`, `drizzle()` даёт объект `db` для запросов. |
| `db/queries.ts` | Запросы. Функция `getProducts` берёт нужную «порцию» товаров и считает, сколько всего страниц. |
| `db/seed.ts` | Заполнение БД. Создаёт таблицу и вставляет 30 товаров. Запускается командой `npm run db:seed`. |
| `app/page.tsx` | Главная страница (серверный компонент). Читает `?page=` из URL, вызывает `getProducts`, рисует сетку и пагинацию. |
| `components/ProductCard.tsx` | Карточка одного товара: картинка, название, описание, цена. |
| `components/ui/pagination.tsx` | Готовый UI-компонент **shadcn/ui**: кнопки страниц, «Назад» и «Вперед». |
| `public/product-1.jpg` … `product-30.jpg` | Сами файлы картинок. В базу они не кладутся. |

Поток данных:

1. Пользователь открывает `/` или `/?page=2`.
2. `app/page.tsx` достаёт номер страницы из `searchParams`.
3. `getProducts(page, 6)` ходит в SQLite через Drizzle.
4. Страница получает `{ products, pages }` и рисует 6 карточек + кнопки.

**Где БД:** файл `sqlite.db` в корне + папка `db/`.  
**Где запросы:** только `db/queries.ts`.  
**Где интерфейс:** `app/page.tsx` и `components/`.

## Как работает пагинация

Пагинация — это показ списка **частями**, а не всех 30 товаров сразу.

На странице всегда **6 товаров** (`pageSize = 6`).  
Всего товаров 30, значит страниц: `30 / 6 = 5`.

### Формула offset

```ts
const offset = (page - 1) * pageSize;
```

`offset` — сколько записей **пропустить** с начала таблицы.

| Страница | Расчёт | offset | Какие товары |
|---|---|---|---|
| 1 | (1 - 1) * 6 | 0 | 1–6 (ничего не пропускаем) |
| 2 | (2 - 1) * 6 | 6 | 7–12 (пропускаем первые 6) |
| 3 | (3 - 1) * 6 | 12 | 13–18 |
| 5 | (5 - 1) * 6 | 24 | 25–30 |

### limit

```ts
.limit(pageSize)  // взять не больше 6 строк
.offset(offset)   // начиная с этой позиции
```

SQL в уме выглядит так: «дай 6 товаров, начиная с 7-го».

### Сколько страниц

```ts
const pages = Math.ceil(total / pageSize);
```

`Math.ceil` округляет вверх. Если бы товаров было 31, страниц было бы 6: на последней остался бы 1 товар.

### Откуда берётся номер страницы

Адрес `/?page=3`.  
Next.js кладёт это в `searchParams`.  
`Number(params.page) || 1` — если параметра нет или он не число, показываем первую страницу.

Кнопки пагинации — обычные ссылки `<a href="?page=2">`. После клика страница загружается заново уже с другой порцией товаров (серверный рендер, без `useState`).

## Как работают картинки

В SQLite в колонке `image` лежит **текст**, например `/product-1.jpg`. Это не сама картинка, а **путь**.

Файлы лежат в папке `public/`:

```
public/product-1.jpg
public/product-2.jpg
...
public/product-30.jpg
```

Правило Next.js: всё из `public` доступно с корня сайта.

- файл: `public/product-1.jpg`
- адрес в браузере: `http://localhost:3000/product-1.jpg`
- в компоненте: `<Image src={product.image} ... />`

Почему так: БД плохо хранит тяжёлые файлы. Проще хранить путь, а картинку отдавать как статику.

## Топ-5 вопросов преподавателя и простые ответы

### 1. Почему страница серверная, а не `"use client"`?

Потому что данные берутся из SQLite на сервере. Серверный компонент может напрямую вызвать `getProducts`. Клиентский компонент в браузере до файла `sqlite.db` не доберётся. Пагинация меняет URL (`?page=`), Next.js заново рендерит страницу на сервере.

### 2. Что такое Drizzle и зачем он, если есть SQL?

Drizzle — ORM. Вместо ручного SQL пишем `db.select().from(products).limit(6)`. Меньше опечаток, есть типы TypeScript (`Product`). Сама база всё равно SQLite, Drizzle только удобная обёртка.

### 3. Объясните offset и limit на примере страницы 2.

`pageSize = 6`, `page = 2`.  
`offset = (2 - 1) * 6 = 6`.  
`limit = 6`.  
Пропускаем первые 6 товаров, берём следующие 6 — это товары с 7-го по 12-й.

### 4. Почему в базе картинка — строка, а не файл?

База хранит данные (название, цена, путь). Картинка — отдельный файл в `public`. Браузер запрашивает `/product-1.jpg`, Next.js отдаёт файл с диска. Так проще и быстрее.

### 5. Откуда берутся 5 кнопок страниц, если в коде нет числа 5?

Число страниц считается: `pages = Math.ceil(total / pageSize)`.  
30 товаров / 6 на страницу = 5.  
В JSX цикл `Array.from({ length: pages }, ...)` рисует столько кнопок, сколько получилось. Если в сиде будет 12 товаров, кнопок станет 2 — менять вёрстку не нужно.

## Как запустить перед защитой

```bash
npm install
npm run db:seed
npm run dev
```

Открыть http://localhost:3000  
Проверить: на первой странице 6 товаров, внизу страницы 1–5, переход на `/?page=5` показывает последние 6 товаров.
